## 2. 与上游的能力关系

本轮以本地共享基线 `f080c8f3`、CodexLink 源码和公开上游快照作对照。2026-09-23 的上游 `main` 快照为 `deab32faa7fa4e82311325985fbf7c8415af0d56`，已发布版本为 `v0.4.1`；两条开发线此后各自演进。远端 Git 抓取失败，因此上游近期内容只作候选核查，未声称完整逐提交审计。

| 能力 | 上游 WebCodex | CodexLink 首版结论 |
| --- | --- | --- |
| Server / Runner、MCP 工具、项目操作、Job 与执行 | 已提供核心实现 | 沿用并强化；不是付费独占技术壁垒 |
| 桌面本机运行和 OpenAI Tunnel | 上游已有相关能力 | 首版产品壳收敛为 `本机 → Engine → Secure Link → ChatGPT`，其他连接形态不在普通客户 UI 中 |
| 授权与交付 | 上游不提供 CodexLink 商业授权链 | 增加 MYWS 设备激活、签名 License、本机校验、bundled Core 启动边界 |
| 上游后续安全/可靠性修复 | 上游继续迭代 | 按实际缺陷逐项移植，不整体合并到封版 1.0 |

已核查的上游候选中，关闭 shell/job stdin 的修复在本 fork 的相应执行路径已有同类处理。上游新增的 MCP Host/Origin DNS rebinding 防护值得在后续安全版本跟进：Desktop 新安装默认把 Server 绑定到 `127.0.0.1`，`/mcp` 经 Bearer 鉴权，POST 还检查 JSON Content-Type 与 Origin；当前尚无无凭证浏览器请求可执行工具的证据。但现有 Origin/Host 检查不等于完整的 Host allowlist，独立开放 Server、`--open` 模式或凭证外泄时应另作威胁复核。上游的安装位置迁移、结构化 MCP 错误、Job receipt 持久化和搜索 fallback 变动也需按本 fork 路径逐项判断，不能直接认定存在相同缺陷。

## 3. 客户真实主链和产品判断

首版目标路径是：购买并取得 MYWS 码 → 安装 → 当前 Windows 用户设备激活 → 自动准备本机 Engine/Runner → 设置 OpenAI Tunnel ID 和受限 Key → 在 ChatGPT 建立 App → 授权项目路径 → 发起真实工具调用。仅看到 `ChatGPT 可访问` 只能证明传输状态，不能证明 ChatGPT App 已成功安装或工具可用；最终验收要完成一次实际调用。

**最大转化风险是购买后的账号配置成本。** 客户需要自己的 ChatGPT 订阅及可创建 App 的账号权限，还要在 OpenAI 页面创建 Tunnel 和受限 Key。网站售前页面应先列明这些前提，并提供购买前兼容性自检；付费后首次引导要用真实账号路径录屏或截图验收，不应把「一键接入」作为承诺。

授权项目目录是用户可选的，但把整个盘符根目录加入授权范围会显著扩大误操作影响。Raw shell/process 以当前 Windows 用户权限执行，授权路径及 cwd 不构成操作系统沙箱。当前 dogfood 截图中出现盘符根路径，不代表产品默认值；销售文案和首发教程应优先建议具体项目目录，界面应在选择盘符根目录时明确提示范围和执行权限。现有 Destructive Guard 是误操作缓解，不能承诺隔离恶意脚本。

首版商业规则已经定为：每枚码绑定一个 Windows 用户下的设备身份，CodexLink 1.x 永久使用；新设备、Windows 重装或更换 Windows 用户须重新购买；普通卸载重装只要本机受保护设备身份保留则不应重复购买。激活后仅本地校验，不为 License 校验持续联网；ChatGPT 使用仍需联网。永久离线签名 License 无法可靠地远程撤销，所以激活后退款只能按人工例外处理。售前必须把设备定义、1.x 范围、重装差异和售后处理写清楚，并做适用规则审查。这种严格的换机政策会增加真实付费用户的售后摩擦，建议保留人工核查渠道，但不能在客户端暗示存在默认转移权。

## 4. 逆向、复制和安全结论

源码中的 bundled product mode、Desktop 启动/阶段签名、DPAPI、进程身份与安装路径检查能提高直接拷贝安装目录或绕过 UI 的成本；License Authority 私钥未放入客户端。它们不能让由购买者控制的 Windows 原生二进制不可补丁化，也不能阻止他使用 Apache-2.0 上游自行部署相似 Core。不能用「无法破解」或「只有 CodexLink 才能运行本地工具」作为卖点。

本轮没有获得与当前源码完全对应的优化构建、签名安装包及独立干净机器，因此**没有完成二进制逆向审计或最终发布验收**。源码边界检查只支持「挡住普通复制与直启」，不支持确定破解所需时间。商业防线应优先放在安装可靠性、配置体验、文档、更新、支持和可验证的交付质量。

## 5. 商业网站的现状

`CodexLink-Deployment-Center` 已有 License Authority 和 Commerce C0/C1 域模型、数据库迁移及幂等准入基础。Commerce 还没有真实 checkout、支付回调验签、订单到授权服务的安全执行通道和完整买家交付闭环；现有支付宝 C2 provider 在创建支付时明确失败，不能用于收款。`portal/` 是旧版 WebCodex Deployment 页面，仍使用 Plus/Pro/Business 与旧产品叙事，不是将来可直接发布的 CodexLink 售卖网站。

支付宝 AI 网页应用收款的商家应用、签约能力、应用身份、RSA2 密钥/支付宝公钥和回调配置需按商户后台实际开通结果核实。域名 ICP 备案只是网站条件之一，不能替代签名材料或支付产品开通。支付成功必须以服务端已验签、已核对金额/商户/订单号的异步通知为准，前端跳转不能发码。Commerce 给 License Authority 传码要走 stdin/受保护通道，避免明文出现在命令行和日志中。

## 6. 发布前的验收门槛

| 优先级 | 门槛 | 完成证据 |
| --- | --- | --- |
| P0 | 以拟发布 commit 构建确切的 bundled Core 和 Windows NSIS 安装包；核对签名、SHA256、组件版本和许可声明 | 可复现构建记录、哈希、安装包内容清单 |
| P0 | 独立干净 Windows 用户/机器验证购买码激活、离线重启、错误码、普通卸载重装和新身份拒绝 | 无敏感信息的步骤与结果记录 |
| P0 | 经 OpenAI Tunnel 与真实 ChatGPT App 做一次读、改、测试及恢复；网络中断与重连也要可解释 | 实际工具调用与状态记录，而非仅「可访问」绿灯 |
| P0 | 在一次性项目目录做 destructive/reparse 负面测试，确认拒绝发生在进程创建前 | 目标路径、结果、无残留子进程的记录 |
| P0 | 网站上线前完成支付验签、订单幂等、发码执行通道、交付与人工退款流程 | 沙箱端到端记录和生产配置核验；当前未完成 |
| P1 | 售前明确账号/订阅、设备身份、1.x 更新范围、售后和非沙箱边界 | 审核后的售卖页与教程文案 |
| P1 | 校对图文教程与最终界面，处理盘符根授权警示，确认初次引导可由非开发者独立完成 | 一次完整用户走查与修订截图 |
| P1 | 按本 fork 的具体暴露模式审查上游后续安全与可靠性修复 | 逐项适用性记录与必要的定点补丁 |

Desktop 源码层封版与「可售安装包通过上述 P0 门槛」是两个不同状态。网站研发可在 Desktop 体验验收过程中设计与实现，但公开收款和交付要以支付、授权及最终安装包均通过为条件。单人开发、无硬截止日时，优先完成 Desktop 发布 Gate，再做网站完整交易闭环；不要让页面视觉先于支付和授权正确性成为上线依据。
